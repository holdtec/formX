# 🛡️ 核心原理与稳健性设计

为了保障在超长依赖链和大规模行明细（如数千行的 ERP 采购单据）的频繁交互下，系统依然能保持极高的运行性能和正确性，`formx-core` 在架构层面实现了四项稳健性保障设计。

---

## 1. Kahn 拓扑排序重算机制 (DAG)

### 痛点：
在常规的响应式系统（如 Vue、MobX、或者原生 DFS 依赖追踪）中，数据变化会触发事件向外层级联传递。
如果表单存在经典的“菱形依赖”（如图所示）：

```
      ┌───► 字段 B ───┐
字段 A                  ├───► 字段 D (总价)
      └───► 字段 C ───┘
```

当 `字段 A` 修改时，普通 DFS 会独立沿着 A-B-D 和 A-C-D 重算两次，导致 `字段 D` 重算了两遍。这会引起多次中间态值设值，并在 UI 层产生数据抖动和重绘毛刺（Glitch 现象）。

### 解决方案：
1. **依赖关系建模**：Formx 在初始化时，会扫描所有包含 `expression` 的字段，建立一张全局的**有向无环图 (Dependency Graph)**。
2. **局部拓扑排序**：当某个具体字段 `A` 变动时，引擎并不立即计算，而是首先通过 `graph.getExecutionOrder('A')` 过滤出受影响的下游子图，并使用 **Kahn 拓扑排序算法** 对其进行排序。
3. **扁平化迭代重算**：拓扑排序保证了所有依赖被合并成一个一维的计算队列（例如 `['B', 'C', 'D']`）。引擎按照该队列顺序依次计算最新值。
4. **效果**：每个下游节点**有且仅被计算一次**，从而达到最高的计算效率，且天然避开了毛刺问题。

---

## 2. 最大递归深度熔断 (Recursion Guard)

### 痛点：
虽然引擎在启动时会对依赖关系执行强环路检查（`detectCycle`），一旦发现 `A -> B -> A` 等公式环会直接报错打断。但开发者在应用层编写逻辑时（如在外部 Store 的 `subscribe` 监听中异步手动 `setValue` 回填数据），可能诱发极其隐蔽的**动态双向依赖死循环**，直接导致浏览器页面崩溃。

### 解决方案：
`setValue` 入口内置了全局事务递归深度的计数器。当单个事件链条的依赖执行深度突破 **`50` 层**（可配阈值）时，引擎将自动触发**熔断保护**：
* 立即退出当前重算队列。
* 在 Console 中输出高亮警告（Warning），指导开发者定位死循环依赖链路。
* 保护了主线程，防止浏览器卡死崩溃。

## 3. 浮点数震荡容差防护 (Epsilon Check)

### 痛点：
前端公式计算常遇到汇率、折扣、税率等浮点数计算。JavaScript 采用 IEEE 754 双精度浮点数标准，计算时会出现 `0.1 + 0.2 === 0.30000000000000004` 等偏差。
这会导致如果原数据已是 `0.3`，重算得到了 `0.30000000000000004`，系统会误判为“数据发生了变更”而错误触发更深链路的重算，引起表单链条的多余震荡。

### 解决方案：
引擎在每次对比更新值（`isValueEqual`）时内置了精度容差防护：
```typescript
if (typeof a === 'number' && typeof b === 'number') {
  return Math.abs(a - b) < Number.EPSILON * 1000;
}
```
凡是在微小容差范围内的浮点数变化，一概被判定为“无实质变动”并直接拦截，从源头上切断了浮点数抖动带来的计算链浪费。

## 4. 无效值安全回落网络 (Safe Fallback)

### 痛点：
在实际输入过程中，用户清空输入框产生空串 `""`，或首期渲染没有填写的字段为 `null`/`undefined`，或者从后端拉取到无效脏数据（如 `"NA"`、`"N/A"`、`"   "`）。如果计算公式直接对其进行乘除，会产生 `NaN` 或抛出 Null 指针错误，导致单据白屏或后面的依赖彻底失效。

### 解决方案：
表达式引擎在变量解析取值阶段，自动对读取的数据进行了安全包裹和类型净化：
* **单值净化**：如果读到 `undefined`、`null`、`NaN` 或非数字类型的字符串（包括带有空格的脏数据与空串），引擎会自动将其回落为**数字 `0`** 参与计算。
* **聚合净化**：对 `SUM(items.amount)` 执行聚合计算时，自动对子表的所有成员数据进行清洗，过滤掉无效行和非数值，避免因单行脏数据导致整张单据合计显示为 `NaN`。
* **效果**：保障表单在未完全填妥的中间状态下，也能呈现出优雅的计算中间值，防止白屏死机。
